# T-A2A 设计:两跳分层 all-to-all

## 结构

一跳基线:dispatch 是一次对整个 EP 组(world = N_g × R)的 `all_to_all_single`,每 token 的 k 行载荷各自直达目的卡——每行都要跨慢链路。

T-A2A 把它拆成两跳:

```
Hop A(跨组,慢链路):token 发往组 g 的载荷只发 1 份,给组 g 里的代表卡
                      (代表 = 与发送方同组内序号的那张卡,纯函数,无需协商)
Hop B(组内,快链路):代表卡把收到的行散给组内真正的专家卡
```

每 token 每目标组:慢链路载荷从 q 行降到 1 行;快侧新增 q(1−1/R) 行(代表卡自己那份不用搬)。**适用判据见 tools/breakeven.py 与 03 篇——这笔交易只在慢链路显著更贵时划算。**

## 数据流(与代码对应)

1. **路由出线格式**:T-Route 产出每 token 的 (组, 组内槽号, 门控) —— `terrace/routing.py`。
2. **计划**:`terrace/ta2a.py::plan_ta2a` 把批内 token 按目标组分桶,产出 Hop A 的发送布局。等额配额下每 (token, 组) 恰 q 个槽号,布局是**定形**的(quota 快路径);无配额时退化为变长路径。
3. **Hop A**:counts 交换(小)+ 载荷 `all_to_all_single`(跨组通信域)。
4. **到达链**:代表卡把收到的 (行, 槽号) 展开成组内散布计划——配对展开、按 owner 卡稳定桶排、组内 counts 直方图、发送缓冲 gather。这一段是纯本地张量操作,也是**融合算子 K1 的目标**(见 04 篇)。
5. **Hop B**:组内 `all_to_all_single`(快侧通信域),把行送到专家卡;门控与槽号元数据可与载荷并包(`terrace/ta2a_pack.py`,小消息合并省一次集合通信的固定开销)。
6. **combine**:镜像反向。

## 反向(autograd 接缝契约)

许多训练栈把 MoE 层前向包在自定义 `autograd.Function` 里(梯度追踪关、反向手写),因此 T-A2A **不依赖外层的 autograd 图**:

- 载荷路走可微的 `_A2A`(`terrace/ep_dist.py`),反向自动是转置的 a2a;
- 元数据路(int,无梯度)走裸 a2a;
- 门控单独挂一条可微边——**不要把门控与载荷焊进同一个融合节点**:外层栈可能对两条输出分别调 `.backward()`,焊死会触发"backward a second time",且第一次会把零梯度写进另一路(我们踩过)。

接入方需要提供的只有两件:dispatch 接缝(用 T-A2A 的 permute 替换原 token_permutation)与 combine 接缝(镜像)。**接入垫片不随库发布**——它与具体训练栈强耦合;本仓库的测试以纯 PyTorch 参考链把守位级正确性(全仓 280 条,CPU 可跑)。

## 已知的结构性成本(诚实清单)

按我们建成后测到底的经验,两跳的成本不止字节:

1. **多一次集合通信的固定开销**。每次 dispatch 从 1 次 a2a 变成 2 次(+counts);固定开销随实现/平台在 0.05–0.5 ms/次量级。小消息(α 主导)场景要单独核账。
2. **变长 splits 需要主机侧同步**。`all_to_all_single` 的 splits 要 Python list——设备到主机的一次取回(~0.04 ms 量级)。这也堵死了朴素的"分块流水两跳重叠":每块都要付一次同步。等额配额让 Hop A 定形免掉这一次,但 Hop B 仍变长。
3. **到达链的本地张量操作不便宜**。展开/桶排/gather 的 PyTorch 组合链在我们的测量里是两跳额外成本的**最大单项**,比字节差还大——这就是 K1 融合算子存在的理由(04 篇)。
4. **Hop B 默认不做卡级去重**:同一 token 发往同卡多个专家仍逐份发。做去重可再省(判据工具的 `--dedup` 档),但需要到达链配合展开。

**这四条在层级化集群上是"要管理的成本",在扁平集群上是"压垮交易的稻草"。先跑判据。**
